# Project Shape

The target shape, validated against `cdktn@0.24.0`, `typescript@7.0.2`, `pnpm@11`, `vitest@4`, and `@biomejs/biome@2.5`.

## Layout

```
.
├── mise.toml                  # node, pnpm, terraform
├── package.json
├── pnpm-workspace.yaml
├── cdktf.json                 # CDKTN config — the filename is still cdktf.json
├── tsconfig.json              # infra: NodeNext ESM
├── biome.jsonc
├── vitest.config.ts
├── src/
│   ├── main.ts                # CDKTN app entrypoint
│   ├── stacks/<stack-name>.ts
│   └── <bundled-app>/         # optional: Worker/Lambda source + its own tsconfig
├── test/<name>.test.ts
├── .gen/                      # generated by `pnpm get`, gitignored
├── LICENSE
└── README.md
```

## `cdktf.json`

```json
{
  "language": "typescript",
  "languageOptions": { "importExtension": ".js" },
  "app": "node --import tsx src/main.ts",
  "output": "cdktn.out",
  "codeMakerOutput": ".gen",
  "projectId": "<uuid, written by the CLI>",
  "sendCrashReports": "false",
  "targetVersions": { "terraform": ">=1.5.7", "opentofu": ">=1.6.0" },
  "terraformProviders": ["<namespace>/<name>@~> <version>"],
  "context": {
    "excludeStackIdFromLogicalIds": "true",
    "allowSepCharsInLogicalIds": "true"
  }
}
```

Keep the two `context` flags when migrating an existing app: dropping them renames every logical ID and forces resource replacement.

## `tsconfig.json`

`.gen/` is deliberately **not** in `include`. Import generated resources by their specific module path (`../../.gen/providers/<p>/<resource>/index.js`) and TypeScript checks only the files actually reached, instead of the entire generated provider.

```json
{
  "compilerOptions": {
    "declaration": false,
    "forceConsistentCasingInFileNames": true,
    "lib": ["ES2025"],
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "noEmit": true,
    "noImplicitReturns": true,
    "noUncheckedIndexedAccess": true,
    "resolveJsonModule": true,
    "skipLibCheck": true,
    "strict": true,
    "strictPropertyInitialization": false,
    "target": "ES2025",
    "types": ["node"]
  },
  "include": ["src/main.ts", "src/stacks/**/*.ts", "test/**/*.ts"],
  "exclude": [".gen", "cdktn.out", "dist", "node_modules"]
}
```

Bundled application code (a Worker, a Lambda) gets its own tsconfig next to it, with the runtime's types and `moduleResolution: "Bundler"`, and is excluded from the root config. `typecheck` runs both.

## `package.json` scripts

```json
{
  "bundle": "wrangler deploy --dry-run --outdir dist",
  "check": "pnpm lint && pnpm typecheck && pnpm test && pnpm synth",
  "deploy": "pnpm bundle && cdktn deploy --auto-approve",
  "destroy": "cdktn destroy --auto-approve",
  "diff": "pnpm bundle && cdktn diff",
  "format": "biome format --write .",
  "get": "cdktn get",
  "lint": "biome check .",
  "lint:fix": "biome check --write .",
  "synth": "pnpm bundle && cdktn synth",
  "test": "vitest run",
  "test:watch": "vitest",
  "typecheck": "tsc --noEmit && tsc --noEmit -p src/<bundled-app>/tsconfig.json"
}
```

Drop the `bundle` script and its chaining when the app has no bundled artifact.

## `mise.toml`

```toml
[tools]
node = "24"
pnpm = "11"
terraform = "1"
```

## `pnpm-workspace.yaml`

```yaml
packages:
  - "."

allowBuilds:
  esbuild: true

minimumReleaseAgeStrict: true
```

Add one entry per package pnpm reports under `ERR_PNPM_IGNORED_BUILDS`, set to `true` or `false` after checking what the install script does.

## `.gitignore` additions beyond the usual

```
.gen/
cdktn.out/
cdktf.out/
*.tfstate
*.tfstate.*
.terraform/
.terraform.lock.hcl
terraform.tfstate.d/
```

`cdktf.out/` is listed because parts of the CLI still fall back to the default output directory name even when `output` is overridden.

## README

Title, one-sentence purpose, prerequisites (the provider's credentials plus a lowercase `mise` bullet linking the words `Install mise` to its installation guide), then:

```sh
mise install
pnpm install
pnpm get
```

`pnpm get` is a separate documented step because `cdktn get` invokes the package manager and cannot be attached to an install hook. Follow with deployment, cleanup, and a short section for anything non-obvious: how a bundled artifact is built, and any dependency pinned below its latest major with the reason.
